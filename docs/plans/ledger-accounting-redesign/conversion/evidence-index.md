# Supabase Conversion Evidence Index

Status: active; no production migration evidence exists yet

## Evidence Standard

Every evidence entry must identify:

- stable manifest surface IDs;
- repository commit and dirty/clean state;
- source export ID/hash where data is involved;
- target environment and migration/contract version;
- exact command or test suite;
- pass/fail result and timestamp;
- artifact path or immutable external reference;
- unexplained differences, blockers, and reviewer/operator; and
- whether the evidence is deterministic, staging-only, or production-derived
  read-only evidence.

Compilation proves only that code compiles. Screenshots prove only the visible
state shown. Neither proves data coverage, security, offline durability,
idempotency, or reconciliation by itself.

## Evidence Classes

| Class | Required proof |
|---|---|
| Source characterization | Code/rules/Function/MCP references plus production-shape profile where applicable |
| Product behavior | Canonical spec/decision ID and acceptance story |
| Target mapping | Reviewed schema/port/command/query/RLS/Sync Stream/migration mapping |
| Implementation | Commit/diff and deterministic tests |
| Security | Grants, RLS, Sync Stream, Storage, Auth, cross-tenant, and negative tests |
| Offline | Physical-device or faithful target test covering restart, reconnect, retry, rejection, and local durability |
| Migration | Source/target counts and hashes, ID coverage, interruption/resume, idempotency, and blockers |
| Reconciliation | Per-source accounting/provenance comparison with zero unexplained differences |
| Cutover | Maintenance/freeze, final delta, rollback boundary, late-writer recovery, operators, and monitoring |
